PI Agent Project Context Architecture

Based on Interpretable Context Methodology: Folder Structure as Agent Architecture. The core idea: use filesystem structure as the agent orchestration layer instead of adding unnecessary framework complexity.

Most Important Takeaways

1. Folder structure becomes the agent brain
Stages, prompts, context and outputs live in files. The agent navigates the workspace instead of relying on heavy orchestration code.
2. One stage = one job
Each stage has a clear input, process and output contract. Avoid mixing research, coding, testing and deployment in one context.
3. Load only relevant context
Do not dump the whole repository into the agent. Give each stage only the files it needs.
4. Separate permanent knowledge from temporary work
Reference material is the factory. Outputs are the product. Keep them separate.
5. Human checkpoints are features
Intermediate outputs should be readable files that humans can review and edit before continuing.
6. Do not over-engineer
Use multi-agent frameworks only when you truly need concurrency, complex branching or dynamic coordination.

PI Agent Operating Rules

  • Read CONTEXT.md before acting.
  • Never load unrelated folders.
  • Write outputs before moving stages.
  • Fix the source rules before repeatedly patching outputs.
  • Keep markdown as the communication layer.

Minimum Viable Setup

Start with: CLAUDE.md + CONTEXT.md + stages + _config. Add complexity only when the project proves it needs it.
